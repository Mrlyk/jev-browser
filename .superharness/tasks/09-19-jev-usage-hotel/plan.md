# jev-browser 用户场景与酒店预订模拟验收

验收对象是当前仓库构建的 jev-browser CLI。通过真实 OpenRouter Jev 选择页面目标，Rust 执行器操作专用 Chromium，Playwright 独立断言并采集视频、截图、业务请求响应。

受控网站是 CLI 的测试消费方，用于复现普通网页和酒店预订交互，不代表任何线上酒店网站。酒店、联系人、价格和订单均为 synthetic，业务 HTTP 接口使用冻结回放。真实调用仅限已授权的 OpenRouter；无真实库存、付款或订单。

## 普通页面

- 打开首页、读取内容、导航到指南、后退与前进。
- 邮箱订阅：正确提交及缺少邮箱时不提交。
- 输入查询并用 Enter 搜索。
- 将页尾滚入视口并点击页尾入口。
- 两个同名“了解更多”按钮不能唯一定位时停止。

## 酒店预订

- 首次列表、城市、关键词、早餐筛选分别核对请求参数与结果。
- 原生入住/离店日期填写与日期不合法分支。
- 详情、两个同名预订按钮对应不同房型、无库存按钮不可用。
- 订单填写校验：缺少入住人、手机号不合法、未同意条款。
- 房间数量改变后的总额；发票选项和抬头。
- 正常提交：酒店 h1、房型 r1、两晚一间 640 元，成功页对应 MOCK-9001。
- 库存不足与价格变更：保留填写页，显示业务错误，不重复提交。

每项功能或独立条件一个 case。测试不依赖上一个 case。不得降低阈值、删除失败项、使用重试掩盖失败、直接调用业务提交 API 代替 UI。发现 CLI 缺陷做最小修复后完整回归。
